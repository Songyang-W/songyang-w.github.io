Grading tremor severity with computer vision

Tremor severity is rated on an ordinal scale. I build computer vision models that learn to assign those grades, and take them from benchmarking all the way to a deployed service.

The problem

What made it hard

A useful model has to grade patients it has never seen. Every comparison therefore uses subject-independent cross-validation: the people in the test set never appear in training.

The model also has to run reliably outside a notebook, so the work covers the full path from data pipeline to a service that other tools can call.

My work

What I built

  • Fair benchmarking

    Compared CNN architectures under subject-independent cross-validation, so scores reflect performance on new patients.

  • Parameter-efficient training

    A small head trained on top of a frozen backbone matched a fully fine-tuned model while training only a tiny fraction of the parameters.

  • Faster training

    Diagnosed GPU starvation caused by sequential CPU augmentation and reconfigured the PyTorch input pipeline with multi-worker overlapped prefetch.

  • Attention ablation

    Showed that where a CBAM attention module sits in a residual CNN, inside the residual branch or after the residual sum, decides whether the model learns or collapses to chance.

  • Deployment

    Shipped the model as a containerized FastAPI inference service on AWS EC2, with the API decoupled from model logic so models can be swapped and tested without touching the interface.

  • Reliable code

    Config-driven preprocessing, training and evaluation modules share one model definition. I also root-caused a silent failure to a train and eval architecture mismatch.
